# 05. 단계별 구현 계획

## 공통 완료 게이트

모든 Phase는 다음 순환을 거친다.

```text
요구사항 확정 → 최소 구현 → 변경 검토 → 정적 검사 → 테스트 → 빌드
→ 브라우저 확인 → 문제 수정 → 재검증 → Phase 승인
```

구현 프로젝트에는 최소한 다음 명령을 마련한다.

- `npm run lint`
- `npm run typecheck`
- `npm run test`
- `npm run test:e2e`
- `npm run build`

실제 이미지 생성이 필요 없는 Phase는 `AI_GENERATION_ENABLED=false`로 진행한다.

## Phase 0. 요구사항 동결과 환경 준비

목표:

- 새 환경에서 문서 전체를 읽고 추가 요구사항을 병합한다.
- 기능 ID, 테스트 ID, 데이터/API 계약을 확정한다.
- Node.js, npm, Git, 환경변수, SQLite 사용 가능 여부를 확인한다.

산출물:

- 요구사항 추적표 초안
- 결정 기록(ADR 또는 동등 문서)
- 새 저장소와 기본 개발 규칙

진입 금지 조건:

- 시나리오 승인과 이미지 생성의 경계가 모호함
- 실제 API 호출을 막는 기본 설정이 없음
- 갤러리 내보내기 계약이 확정되지 않음

## Phase 1. 앱 골격과 로컬 저장소

목표:

- Next.js App Router, TypeScript, Tailwind CSS를 설정한다.
- Prisma와 SQLite 연결, 초기 마이그레이션을 구성한다.
- 공통 레이아웃, 오류 화면, 로딩 화면을 마련한다.

검수 포인트:

- 빈 DB에서 설치·실행 가능
- 환경변수 누락 시 이해 가능한 안내
- 브라우저 번들에 서버 비밀값이 포함되지 않음

## Phase 2. 프로젝트·용어 관리

목표:

- 웹툰 프로젝트 생성, 조회, 수정, 보관 흐름을 구현한다.
- 용어, 설명, 대상 독자, 톤, 추가 요청을 저장한다.
- 기존 100개 용어는 이미지 유무와 관계없이 검색 가능하게 한다.

검수 포인트:

- 유효성 오류와 빈 상태
- 중복 저장 방지
- 이미지가 없는 용어도 검색 결과에 표시

## Phase 3. 4컷 시나리오 생성·편집·승인

목표:

- 서버에서 OpenAI Responses API를 호출하는 텍스트 어댑터를 구현한다.
- Zod 기반 구조화 출력으로 4개 패널을 받는다.
- 사용자가 패널별 장면·대사·설명을 수정하고 새 버전을 저장한다.
- 명시적 승인 후에만 이미지 단계로 전환한다.

검수 포인트:

- 결과가 정확히 4개 패널인지 확인
- 재생성 시 이전 버전 보존
- API 장애가 기존 프로젝트와 100개 용어 검색을 막지 않음
- 이 Phase에서는 이미지 API 호출이 0회

## Phase 4. 이미지 생성과 비용 안전장치

목표:

- 승인된 시나리오의 패널별 이미지 생성을 구현한다.
- 서버 잠금, 중복 요청 키, 진행 상태, 실패 재시도를 적용한다.
- 실제 생성과 목업 모드를 화면에서 명확히 구분한다.

검수 포인트:

- 승인 전 호출 차단
- 빠른 연속 클릭과 새로고침에도 중복 생성 차단
- 패널 단위 재시도 가능
- 생성 모델·프롬프트·옵션·시간·상태 기록
- 실제 호출 전 사용자에게 비용 발생 가능성을 명확히 표시

## Phase 5. 이미지 품질 검수와 재생성

목표:

- 전체 4컷과 패널별 검수 화면을 만든다.
- 글자, 인물, 의미, 구도, 정책/안전 항목을 별도로 기록한다.
- 실패 패널만 수정 지시와 함께 재생성한다.

검수 포인트:

- 탈락 사유 없이 재생성할 수 없음
- 새 결과가 이전 결과를 덮어쓰지 않음
- 전체 통과 전 최종 내보내기 차단

## Phase 6. WebP·메타데이터·갤러리 내보내기

목표:

- 승인된 결과만 WebP로 준비한다.
- `docs/03_TECH_DATA_API.md`의 정확한 폴더 및 JSON 계약으로 내보낸다.
- 갤러리 import 검증과 중복 ID 검사를 수행한다.

검수 포인트:

- 이미지와 JSON의 파일명·패널 순서 일치
- 한국어 문자 깨짐 없음
- 출처와 생성 이력 보존
- 실패 시 부분 내보내기 잔재를 정리하거나 안전하게 복구 가능

## Phase 7. 기존 자료 선택적 이관

목표:

- 기존 1~10번 결과물은 원본을 보존하며 선택적으로 가져온다.
- 프롬프트가 없는 자산은 `promptUnavailable: true`로 표시한다.
- 기존 100개 용어 목록을 검증해 가져온다.

검수 포인트:

- 기존 파일을 덮어쓰지 않음
- 중복 용어와 충돌 ID 보고
- 이관 전후 개수·해시 또는 동등한 무결성 확인

## Phase 8. 운영 준비와 최종 인수

목표:

- 새 환경 설치 문서, 백업/복구, 장애 대응, 업데이트 절차를 검증한다.
- 전체 사용자 흐름을 E2E로 재검수한다.
- 남은 제한과 이후 요구사항을 명시한다.

최종 완료 조건:

- lint, typecheck, unit/integration, E2E, build 통과
- 새 DB와 복원 DB 양쪽에서 핵심 흐름 통과
- 기능검수 에이전트의 `PASS`
- 운영 에이전트의 복구 훈련 통과
- 사용자에게 실제 API 호출 횟수와 비용 관련 기록 보고
