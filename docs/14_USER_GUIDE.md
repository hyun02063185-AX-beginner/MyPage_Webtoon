# 개인용 웹툰 제작 도구 사용 설명서

이 도구는 혼자 웹툰을 제작·관리하고, 완료한 결과만 MyPage 갤러리에 내보내기 위한 로컬 도구입니다. 방문자는 내보낸 결과만 보며 이 화면에서 생성하거나 검수하지 않습니다.

## 1. 시작하기

프로젝트 루트에서 다음을 실행하고 브라우저로 `http://localhost:3000`을 엽니다.

```powershell
npm run dev
```

첫 사용이거나 DB가 없는 환경이라면 먼저 의존성·DB를 준비합니다.

```powershell
npm ci
npm run prisma:generate
npm run prisma:migrate
npm run prisma:seed
```

## 2. API 키 설정과 LIVE 모드

`.env.local`에만 API 키를 둡니다. 키를 문서·Git·브라우저 코드에 넣지 않습니다.

```dotenv
OPENAI_API_KEY=새로_발급한_API_키
AI_GENERATION_ENABLED=true
AI_GENERATION_MODE=live
OPENAI_IMAGE_MODEL=gpt-image-2
OPENAI_IMAGE_SIZE=1536x1024
OPENAI_IMAGE_QUALITY=medium
WEBP_QUALITY=82
```

저장한 뒤에는 개발 서버를 종료하고 `npm run dev`로 다시 시작합니다. 홈 화면의 `AI 생성 모드: LIVE` 표기로 설정을 확인합니다.

현재 설정된 키는 환경 파일에는 존재하지만 OpenAI가 HTTP 401로 인증을 거부했습니다. [OpenAI Platform API keys](https://platform.openai.com/api-keys)에서 해당 프로젝트의 유효한 API 키를 새로 만들거나 상태를 확인한 뒤 위 값을 교체해야 합니다. API 키는 서버 환경 변수로만 보관해야 합니다.

개인용 도구이므로 별도의 사용자 승인 화면이나 횟수·비용 상한 기능은 두지 않습니다. 다만 실수로 같은 이미지를 두 번 요청하지 않도록 시나리오 승인, 서버 잠금, 멱등성 처리는 유지됩니다.

## 3. 웹툰 하나 만들기

1. 홈에서 `개념`, `대상 독자`, `목적`, `스타일`을 입력하고 **프로젝트 만들기**를 누릅니다.
2. 프로젝트 화면 2단계에서 **MOCK 시나리오 만들기**를 누릅니다.
3. 4개 컷의 장면·대사·최종 캡션을 읽고 필요하면 수정한 뒤 새 버전으로 저장합니다.
4. 내용이 맞으면 **이 시나리오 버전 승인**을 누릅니다.
5. 3단계의 최종 프롬프트와 모델·크기·품질을 확인하고 **LIVE 이미지 생성**을 누릅니다. 이 버튼은 실제 OpenAI Image API 요청을 한 번 보냅니다.

이 도구의 신규 생성은 컷별 이미지 네 장을 따로 만든 뒤 합치는 방식이 아닙니다. 2단계에서 4개 컷의 시나리오를 정리하고, 3단계에서 **4컷이 들어간 이미지 한 장**을 생성합니다.

시나리오 초안 생성은 현재 의도적으로 MOCK입니다. 실제 이미지 생성과 혼동되지 않게 화면에도 MOCK으로 표시됩니다. 필요한 문구와 장면은 승인 전 직접 수정하면 됩니다.

## 4. 이미지 확인과 재생성

- 생성이 성공하면 4단계에서 결과 이미지와 컷별 예상 대사를 비교합니다.
- `정상`, `오타`, `누락`, `잘림`, `배치 문제`, `기타`를 각 컷에 기록합니다.
- 문제가 있으면 반려 사유를 남기고, 같은 프롬프트 재생성 또는 수정 지시를 추가한 재생성 중 하나를 선택합니다.
- 실패한 요청은 성공으로 바꾸지 않으며, 생성 이력에서 오류 코드·프롬프트 해시·옵션을 확인할 수 있습니다.

사람이 실제 한글 문구와 컷 배치를 확인하기 전에는 내보내지 않습니다.

## 5. 갤러리용 내보내기

1. LIVE 이미지가 준비되고 모든 컷의 사람 검수가 통과한 뒤 5단계로 갑니다.
2. `slug`, 갤러리 제목, `imageAlt`, 해설을 입력하고 **메타데이터 저장·검증**을 누릅니다.
3. 조건이 모두 맞으면 **WebP + JSON 묶음 내보내기**가 활성화됩니다.

MOCK 이미지는 최종 내보내기 대상이 아닙니다.

## 6. 이전 백업 이미지 내보내기

`과거 이미지 후보 검토`에서 선택한 항목은 처음에는 계획으로만 표시됩니다. 이는 원본 프롬프트가 없는 과거 자산을 새 LIVE 생성물로 오인하지 않기 위한 동작입니다.

1. 홈의 **과거 이미지 후보 검토하기**를 엽니다.
2. 원본을 미리 본 뒤 필요한 항목을 선택하고 **선택한 후보로 이관 준비 계획 보기**를 누릅니다.
3. 아래의 **선택한 N개를 LEGACY 이관·검수 준비**를 누릅니다.
4. 도구가 원본 SHA-256을 다시 확인하고, 원본을 수정하지 않은 채 관리용 WebP 사본과 `LEGACY` 프로젝트를 만듭니다.
5. 이관된 프로젝트는 2단계·3단계를 건너뛰고 바로 4단계에서 실제 이미지의 대사·잘림·배치를 사람이 검수합니다. 갤러리 메타데이터를 입력한 뒤 내보냅니다.

이 경로는 OpenAI API를 호출하지 않습니다. 내보낸 JSON에는 원본 프롬프트가 없다는 사실과 `LEGACY_ORIGINAL` 출처가 남으며, 임의의 프롬프트를 만들지 않습니다.

## 7. 유지보수

중요한 생성이나 내보내기 전후에는 백업을 만듭니다.

```powershell
npm run ops:backup
```

코드를 수정한 뒤에는 다음 검사를 실행합니다.

```powershell
npm run lint
npm run typecheck
npm run test
npm run test:e2e
npm run build
```

`npm run test:e2e`는 이제 별도 테스트 DB만 사용합니다. 기존 운영 DB에 남아 있는 이전 테스트 프로젝트는 자동으로 지워지지 않으므로, 필요하면 실제 제작 프로젝트와 구분해 한 번 정리합니다.
