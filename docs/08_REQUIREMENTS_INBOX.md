# 08. 추가 요구사항 입력함

이 문서는 사용자가 새로 떠올린 요구사항을 자유롭게 붙이는 공간이다. 문장을 완성하거나 기존 문서 형식에 맞출 필요가 없다. 작업을 시작하는 에이전트가 내용을 분석해 기능명세와 테스트 기준으로 정리한다.

## 사용 방법

1. 아래 `사용자 메모` 영역에 원하는 내용을 그대로 추가한다.
2. 삭제보다 취소선 또는 상태 변경을 사용해 의사결정 이력을 남긴다.
3. 새 환경에서 `docs/09_KICKOFF_PROMPT.md`를 에이전트에게 전달한다.
4. 에이전트가 제시한 충돌·비용·범위 분석을 확인한 뒤 구현 범위를 승인한다.

## 정리된 요구사항 대장

에이전트가 사용자 메모를 분석한 뒤 아래 표에 추가한다. 원문은 위에서 지우지 않는다.

| 요구사항 ID | 제목 | 상태 | 우선순위 | 관련 기능 | 메모 |
|---|---|---|---|---|---|
| REQ-20260906-001 | 과거 이미지 형식·크기 참조 및 보존 | APPROVED | Must | F-014, F-021 | `backup_images/`의 원본은 읽기 전용 참조 자산이며 Phase 7 전 운영 데이터가 아니다. |
| REQ-20260906-002 | GitHub 저장소 기반 소스 관리 | APPROVED | Must | F-020 | 지정 원격 저장소와 GitHub noreply 커밋 이메일을 사용한다. |
| REQ-20260906-003 | 기존 100개 용어 원본 미확보 | NEEDS_DECISION | Must | F-002, F-021 | 원본을 찾지 못했음이 확인되었다. 과거 100개 목록으로 표시할 신규 데이터 생성은 별도 승인 없이는 하지 않으며, Phase 2 완료 전 초기 데이터 경로를 결정해야 한다. |

상태 값:

- `PROPOSED`: 입력되었으나 분석 전
- `NEEDS_DECISION`: 충돌 또는 사용자 선택 필요
- `APPROVED`: 구현 범위 승인
- `DEFERRED`: 이후 단계로 연기
- `REJECTED`: 제외 사유 기록
- `DONE`: 구현과 검수 완료

## 요구사항 상세 양식

필요할 때 에이전트가 다음 형식으로 정리한다.

```markdown
### REQ-YYYYMMDD-NNN — 제목

- 원문:
- 해결하려는 문제:
- 사용자/사용 장면:
- 원하는 결과:
- 필수 여부: Must / Should / Could
- 수용 기준:
  - Given:
  - When:
  - Then:
- 기존 기능과의 충돌:
- 데이터/API/비용/운영 영향:
- 관련 기능 ID:
- 관련 테스트 ID:
- 상태:
- 결정 및 이유:
```

## 분석 규칙

- “예쁘게”, “빠르게”, “잘 되게” 같은 표현은 측정 가능한 기준으로 바꾼다.
- 실제 이미지 생성 횟수나 비용이 늘어나는 요구사항은 별도 표시한다.
- 기존 데이터 삭제, 외부 공개, 계정 연결, 결제는 사용자 승인 없이는 범위에 넣지 않는다.
- 현재 기능과 충돌하면 임의로 하나를 선택하지 않고 선택지와 영향을 제시한다.
- 승인된 요구사항마다 기능 ID와 테스트 ID를 연결한다.

### REQ-20260906-001 — 과거 이미지 형식·크기 참조 및 보존

- 원문: `C:\\Users\\hyun0\\MyPage_Webtoon\\backup_images`에 이전 교육용 만화가 있으며, 크기나 형식이 통일되지 않았을 때의 예시로 작업 시 참조한다.
- 해결하려는 문제: 과거 결과물의 규격 차이를 새 export와 이관 과정에서 반복하지 않는다.
- 사용자/사용 장면: 제작자가 기존 결과를 참고하거나 Phase 7에서 자산 이관 여부를 검토한다.
- 원하는 결과: 원본은 변경·이름 변경·자동 등록 없이 보존하고, 형식·크기 차이는 manifest/검토 화면에서 식별 가능하다.
- 필수 여부: Must
- 수용 기준:
  - Given: `backup_images/`에 원본 이미지가 있다.
  - When: 참조 또는 이관 후보를 점검한다.
  - Then: 파일명·해시·형식·해상도를 기록할 수 있고 원본 파일은 변경하지 않는다.
  - Then: 서로 다른 규격은 새 갤러리 export 규격과 혼동되지 않게 표시한다.
- 기존 기능과의 충돌: 없음. Phase 7 전에는 신규 시스템의 운영 데이터로 취급하지 않는다.
- 데이터/API/비용/운영 영향: 로컬 읽기 전용 파일 검사만 필요하며 API 비용은 없다. `backup_images/`는 Git 추적에서 제외한다.
- 관련 기능 ID: F-014, F-021
- 관련 테스트 ID: T-UNIT-014, T-INT-021, T-MANUAL-021
- 상태: APPROVED
- 결정 및 이유: 사용자가 참조와 원본 보존을 명시했다. 실제 이관 범위는 Phase 7에서 별도 선택한다.

### REQ-20260906-002 — GitHub 저장소 기반 소스 관리

- 원문: `https://github.com/hyun02063185-AX-beginner/MyPage_Webtoon`에서 소스를 관리하고 `288177832+hyun02063185-AX-beginner@users.noreply.github.com`을 활용한다.
- 해결하려는 문제: 소스·문서 이력을 지정 저장소에서 일관되게 관리한다.
- 사용자/사용 장면: 개발자가 Phase별 변경을 Git으로 추적·공유한다.
- 원하는 결과: 로컬 `main` 브랜치와 지정 원격 `origin`을 사용하며, 저장소 단위 커밋 이메일은 지정된 noreply 주소다.
- 필수 여부: Must
- 수용 기준:
  - Given: 새 작업 폴더다.
  - When: Git 상태를 초기화·점검한다.
  - Then: `origin`은 지정한 GitHub 저장소이고 로컬 커밋 이메일은 지정 noreply 주소다.
  - Then: API 키, 런타임 DB, 생성물, 과거 원본 이미지는 Git에 추가되지 않는다.
- 기존 기능과의 충돌: 없음.
- 데이터/API/비용/운영 영향: 원격 push는 사용자가 승인한 소스 관리 범위에서만 수행하며 OpenAI 비용은 없다.
- 관련 기능 ID: F-020
- 관련 테스트 ID: T-OPS-002
- 상태: APPROVED
- 결정 및 이유: 사용자가 최신 명시 요구사항으로 지정했다.

### REQ-20260906-003 — 기존 100개 용어 원본 미확보

- 원문: `기존 100개 용어 원본은 못찾겠어`
- 해결하려는 문제: 원본이 없는 상태에서 임의 목록을 과거 100개 용어 데이터로 오인·표시하거나, F-002의 검색 수용 기준을 근거 없이 통과 처리하는 일을 막는다.
- 사용자/사용 장면: 제작자가 Phase 2에서 프로젝트와 기존 용어를 검색하고, Phase 7에서 과거 자료 이관 여부를 검토한다.
- 원하는 결과: 원본 미확보 사실을 보존하고, 승인된 출처 또는 별도 승인된 신규 초기 데이터셋만 검색 대상으로 사용한다.
- 필수 여부: Must. F-002의 기존 용어 검색 자체는 필수이나, 원본 대체 데이터의 작성 범위는 아직 승인되지 않았다.
- 수용 기준:
  - Given: 기존 100개 용어 원본을 찾지 못한 상태다.
  - When: Phase 2의 용어 검색 데이터와 테스트 데이터를 준비한다.
  - Then: 임의로 만든 목록을 `기존 100개 용어` 또는 이관 원본으로 표시하지 않는다.
  - Then: 원본 제공, 승인된 외부/기존 출처 확인, 또는 사용자 승인 신규 초기 데이터셋 중 하나의 데이터 경로와 출처를 기록한다.
  - Then: 선택된 데이터 경로가 없으면 프로젝트 CRUD는 검증할 수 있어도 기존 100개 용어 검색의 완료·수용 테스트는 통과로 기록하지 않는다.
- 기존 기능과의 충돌: F-002와 Phase 2의 `기존 100개 용어는 이미지 유무와 관계없이 검색 가능` 목표는 유지한다. 원본 부재가 해당 목표를 제외하거나 축소하는 근거는 아니다.
- 데이터/API/비용/운영 영향: Phase 1에는 영향이 없고 OpenAI API 비용도 없다. 신규 데이터셋을 만들거나 외부 데이터를 가져오는 일은 데이터 범위·저작권·검증 기준을 정하는 별도 사용자 승인 후에만 한다. 원본을 나중에 찾으면 `legacy-input/data/`에 읽기 전용으로 보관하고 Phase 7에서 검증 이관한다.
- 관련 기능 ID: F-002, F-021
- 관련 테스트 ID: T-E2E-002 (Phase 2 검색 흐름), `docs/06_TEST_ACCEPTANCE.md` §4-D (기존 검색 장애 격리), T-INT-021 (Phase 7 이관 검증)
- 상태: NEEDS_DECISION
- 결정 및 이유: 사용자가 원본을 찾지 못했다고 명시했다. 권장안은 Phase 2 진입 전에 사용자에게 데이터 경로를 확인받는 것이다. 확인 전에도 Phase 1 골격은 진행할 수 있으나, Phase 2에서 F-002 완료 판정은 보류한다.
