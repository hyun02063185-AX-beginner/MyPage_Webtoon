# 06. 테스트 및 기능검수 기준

## 1. 추적 원칙

모든 승인된 요구사항에는 최소 하나의 테스트가 연결되어야 한다.

| 요구사항 ID | 테스트 ID | 종류 | 자동/수동 | 결과 | 증거 |
|---|---|---|---|---|---|
| F-001 | T-E2E-001 | 사용자 흐름 | 자동 | 미실행 | - |

기능을 수정할 때는 연결된 기존 테스트를 먼저 확인하고, 회귀 위험이 있으면 테스트도 함께 갱신한다.

## 2. 테스트 계층

### 단위 테스트

- Zod 입력/출력 검증
- 상태 전이 허용/차단 규칙
- 프롬프트 조합 로직
- 파일명과 export JSON 생성
- 중복 요청 키와 잠금 판정

### 통합 테스트

- API Route/Server Action과 SQLite 연결
- 시나리오 버전 보존
- 이미지 생성 성공·실패 상태 기록
- 내보내기 전 검수 상태 확인
- AI 어댑터의 목업 응답 및 오류 격리

### E2E 테스트

- 프로젝트 생성 → 시나리오 생성 → 수정 → 승인
- 승인 전 이미지 생성 차단
- 승인 후 목업 이미지 생성 → 패널 검수 → 최종 승인
- 갤러리 내보내기와 결과 확인
- 기존 용어 검색이 AI 장애 중에도 동작

### 수동 시각 검수

- 데스크톱과 좁은 화면의 배치
- 긴 한국어 용어·대사 줄바꿈
- 로딩, 실패, 빈 상태, 재시도 안내
- 클릭 연타 시 버튼 잠금과 상태 피드백

## 3. 실행 모드

| 모드 | 환경 설정 | 목적 | 비용 |
|---|---|---|---|
| OFF | `AI_GENERATION_ENABLED=false` | 일반 개발·검색·CRUD | 없음 |
| MOCK | `AI_GENERATION_MODE=mock` | 전체 흐름과 자동 테스트 | 없음 |
| LIVE | `AI_GENERATION_ENABLED=true`, `AI_GENERATION_MODE=live` | 제한된 최종 통합 검수 | 발생 가능 |

목업 결과는 모든 화면과 데이터에 `MOCK`으로 표시하며 최종 export를 금지한다.

## 4. 핵심 수용 시나리오

### A. 시나리오 승인 경계

1. 사용자가 용어와 설명을 입력한다.
2. 시스템이 4개 패널 시나리오를 제시한다.
3. 사용자가 2번 패널의 대사를 수정한다.
4. 승인 전 이미지 생성 버튼을 눌러도 호출되지 않는다.
5. 승인 후에만 이미지 생성이 가능하다.

합격 기준: 수정 버전과 승인 버전이 저장되고, 승인 전 이미지 호출 기록이 0건이다.

### B. 중복 과금 방지

1. 같은 프로젝트에서 이미지 생성 버튼을 빠르게 여러 번 누른다.
2. 생성 중 새로고침 후 다시 요청한다.

합격 기준: 활성 생성 작업은 하나이며, 동일 요청은 기존 작업 상태를 반환한다.

### C. 부분 실패 복구

1. 4개 중 한 패널만 실패하도록 AI 어댑터를 설정한다.
2. 실패 패널을 다시 생성한다.

합격 기준: 성공한 3개 패널은 유지되고 실패 패널에만 새 시도 기록이 추가된다.

### D. 기존 검색 장애 격리

1. OpenAI 어댑터를 오류 상태로 둔다.
2. 기존 100개 용어를 검색한다.

합격 기준: 검색은 정상 동작하고 생성 기능에만 오류 안내가 표시된다.

### E. 내보내기 무결성

1. 전 패널을 통과 처리한다.
2. 갤러리 묶음을 내보낸다.
3. 별도 검증기로 JSON과 WebP 파일을 읽는다.

합격 기준: 스키마, 파일 존재, 순서, ID, UTF-8 한국어가 모두 유효하다.

## 5. 이미지 품질 검수표

각 패널을 독립적으로 판정한 뒤 전체 일관성을 다시 판정한다.

| 항목 | 합격 기준 |
|---|---|
| 한국어 글자 | 글자가 잘리지 않고 읽을 수 있으며 의미가 맞음 |
| 인물 일관성 | 주요 인물의 얼굴·복장·특징이 패널 사이에서 유지됨 |
| 개념 정확성 | 용어 설명과 장면·대사가 충돌하지 않음 |
| 패널 구도 | 핵심 행동과 말풍선이 명확하며 중요한 요소가 가려지지 않음 |
| 대사 순서 | 읽는 순서와 화자가 혼동되지 않음 |
| 여백 | 갤러리 크롭이나 WebP 변환 후에도 내용이 안전 영역 안에 있음 |
| 스타일 | 지정한 톤과 시각 스타일이 4컷 전체에서 유지됨 |
| 안전성 | 부적절한 개인정보·상표 오인·정책 위반 요소가 없음 |

하나라도 핵심 항목이 실패하면 해당 패널은 `REJECTED`이며 사유를 기록해야 한다.

## 6. 보안·운영 검수

- 브라우저 소스와 네트워크 응답에 API 키가 없다.
- `.env*`, DB, 생성 원본이 Git에 실수로 포함되지 않는다.
- 로그에 인증값이 마스킹된다.
- DB 마이그레이션 전 백업이 생성된다.
- 복원 검증은 원본 DB가 아닌 별도 임시 DB에서 수행한다.
- OpenAI 장애·시간 초과·제한 응답을 사용자에게 이해 가능한 상태로 표시한다.

## 8. 완료 판정

다음 상태에서는 완료라고 하지 않는다.

- 필수 자동 검증 중 하나라도 실패
- 브라우저 확인을 생략
- LIVE 호출 결과만 성공하고 MOCK/OFF 경로가 실패
- 이미지 품질 탈락 패널을 승인 처리
- 백업 없이 파괴적 마이그레이션 실행
- 실행하지 않은 테스트를 통과로 기록
