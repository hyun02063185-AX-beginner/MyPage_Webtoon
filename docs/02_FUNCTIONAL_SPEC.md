# 02. 기능 명세와 사용자 흐름

## 1. 핵심 사용자

- 주 사용자: 웹툰을 제작하는 AX 전문강사 본인
- 결과 소비자: MyPage 갤러리를 방문하는 교육 담당자와 학습자
- 생성기는 비공개이므로 방문자용 탐색 기능보다 제작 이력과 검수 정확성을 우선한다.

## 2. 정보 구조

```text
/
├─ 프로젝트 목록과 최근 작업
├─ /projects/new
├─ /projects/{projectId}
│  ├─ 기본 정보
│  ├─ 시나리오
│  ├─ 이미지 생성 시도
│  ├─ 검수
│  └─ 갤러리 메타데이터·내보내기
├─ /settings
└─ /maintenance
```

## 3. 기능 요구사항

| ID | 기능 | 완료 기준 |
|---|---|---|
| F-001 | 프로젝트 생성 | 개념, 대상, 목적, 스타일, 메모를 저장한다. |
| F-002 | 프로젝트 목록·검색 | 상태, 개념, 최근 수정일로 기존 작업을 찾는다. |
| F-003 | 구조화 시나리오 생성 | Responses API 결과를 Zod로 검증하고 정확히 4개 패널로 저장한다. |
| F-004 | 시나리오 수정·버전 | 수정할 때 새 버전을 만들며 이전 버전을 보존한다. |
| F-005 | 시나리오 승인 | 승인 시각과 승인 버전을 서버가 기록한다. |
| F-006 | 최종 프롬프트 표시 | 실제 API 전송 전에 프롬프트 전문과 모델·옵션을 확인할 수 있다. |
| F-007 | 이미지 생성 | 승인된 시나리오 버전만 사용하고 중복 요청을 서버에서 막는다. |
| F-008 | 생성 시도 이력 | 성공, 실패, 반려, 통과 결과를 모두 버전별로 보존한다. |
| F-009 | 이미지 비교 | 현재 시도와 이전 시도를 나란히 비교한다. |
| F-010 | 한글 검수 | 컷별 예상 대사와 이미지를 비교하고 문제 유형과 메모를 저장한다. |
| F-011 | 재생성 | 같은 프롬프트와 수정 프롬프트 재생성을 구분하고 부모 시도를 연결한다. |
| F-012 | 최종 검수 통과 | 사람의 명시적 통과와 검수표 완료가 필요하다. |
| F-013 | 갤러리 메타데이터 | slug, concept, title, imageAlt, paragraphs를 편집·검증한다. |
| F-014 | WebP export | 검수 통과 이미지로 WebP를 만들고 파일 무결성을 검사한다. |
| F-015 | JSON export | 정해진 갤러리 계약과 일치하는 JSON을 만든다. |
| F-016 | 묶음 다운로드 | WebP와 JSON을 한 폴더 또는 ZIP으로 받을 수 있다. |
| F-017 | 실패 복구 | API 실패 후 승인된 시나리오와 프롬프트를 유지하고 안전하게 재시도한다. |
| F-018 | 비용 보호 | 프론트와 서버 중복 차단, 동시성 1, 실제 호출 감사 기록을 제공한다. |
| F-019 | 설정 점검 | 키 값은 노출하지 않고 모델, 모드, 저장 경로의 설정 여부만 보여준다. |
| F-020 | 백업·복원 | DB, 이미지, export를 함께 백업하고 새 환경에서 복원 검증한다. |
| F-021 | 과거 자산 가져오기 | 선택 기능이며 프롬프트 부재와 출처를 명확히 표시한다. |
| F-022 | 접근성·반응형 | 키보드 조작, 초점, 레이블, 확대, 모바일 세로 흐름을 지원한다. |

## 4. 대표 제작 흐름

```text
새 프로젝트
→ 개념·대상·목적 입력
→ 4컷 시나리오 생성
→ 시나리오 수정
→ 시나리오 승인
→ 실제 이미지 프롬프트 확인
→ 이미지 생성
→ 이미지와 예상 대사 대조
→ 문제 없으면 검수 통과
→ 문제 있으면 사유 기록 후 재생성
→ 제목·imageAlt·paragraphs 작성
→ WebP + JSON 사전 검증
→ 최종 export
```

## 5. 한글 검수 화면 요구사항

- 큰 이미지와 확대 기능
- 1~4컷 예상 대사 목록
- 각 컷별 문제 유형 선택
- 전체 통과 체크박스
- 자유 검수 메모
- `오타 있음 — 같은 프롬프트 재생성`
- `오타 있음 — 프롬프트 수정 후 재생성`
- `구성 문제 — 시나리오로 돌아가기`
- `검수 통과`
- 이전 생성본 비교

검수 통과 버튼은 문제 항목이 남아 있거나 필요한 확인란이 비어 있으면 비활성화한다.

## 6. 갤러리 메타데이터 편집

- `slug`: ASCII 소문자와 하이픈, 중복 금지
- `concept`: 공개할 용어
- `title`: 방문자가 읽을 소개 제목
- `imageAlt`: 이미지 속 4개 장면과 핵심 메시지를 설명하는 문장
- `prompt`: 선택한 최종 이미지 시도의 실제 프롬프트, 편집 금지
- `model`: 해당 시도의 실제 모델 기록, 편집 금지
- `createdAt`: 최종 export 기준 날짜
- `paragraphs`: 사람이 작성하는 해설 문단 배열

## 7. 오류 UX

- 사용자 메시지는 다음 행동을 알려주는 한국어로 표시한다.
- 세부 오류와 요청 ID는 진단 화면에 분리한다.
- API 키 누락, 사용 중지, 승인 누락, 중복 생성, 속도 제한, 안전 차단, 파일 저장 실패, JSON 검증 실패를 구분한다.
- 오류가 발생해도 작성한 입력, 시나리오, 프롬프트, 검수 메모를 잃지 않는다.
