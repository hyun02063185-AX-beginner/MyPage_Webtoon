# 00. START HERE

## 1. 이 문서 묶음의 역할

이 패키지는 원본 노트북이나 기존 저장소가 없는 환경에서도 웹툰 생성기 V3를 새로 구축하기 위한 기준 문서다. 과거 앱을 복원하는 것이 아니라, 과거 결과에서 배운 문제를 반영해 제작 도구를 다시 설계한다.

## 2. 시작 전 사용자 작업

1. 빈 Git 저장소를 만든다.
2. 이 패키지 전체를 저장소 루트에 복사한다.
3. `docs/08_REQUIREMENTS_INBOX.md`에 새 요구사항을 붙인다.
4. 로컬 전용 `.env`와 `.env.local`을 준비한다.
5. 과거 이미지가 있으면 별도 폴더에 모으되 아직 `public`이나 최종 export 폴더로 복사하지 않는다.

## 3. 에이전트가 가장 먼저 할 일

Phase 0에서는 코드를 만들지 않는다. 다음만 점검하고 사용자에게 보고한다.

- 문서 전체가 존재하는지
- 추가 요구사항과 기존 기획이 충돌하는지
- 새 환경의 Node.js, npm, Git 상태
- API 키의 존재 여부만 확인하되 값을 출력하지 않았는지
- 가져올 과거 자산의 존재 여부와 수량
- 모델 및 SDK 사용법의 공식 문서 확인 결과
- Phase별 계획과 위험 요소
- 첫 실제 비용 발생 API 호출 전까지의 무비용 개발 범위

## 4. 기본 가정

사용자가 별도로 변경하지 않으면 다음을 기본값으로 사용한다.

- 한 명이 로컬에서 사용하는 비공개 제작 도구다.
- 로그인과 다중 사용자 권한은 범위에서 제외한다.
- MyPage 갤러리와 저장소를 분리한다.
- 생성기는 WebP와 JSON을 파일로 내보낸다.
- 원본 생성 이미지와 모든 시도 이력을 로컬에 보관한다.
- 해설 `paragraphs`는 사람이 작성한다.
- `imageAlt`는 AI가 초안을 제안할 수 있지만 사람이 확인·수정한다.
- 한글 이미지 검수는 사람의 명시적 통과 처리가 필요하다.
- 갤러리 페이지는 이 프로젝트에서 만들지 않는다.

## 5. 아직 확정하지 않는 항목

- 새 컴퓨터의 운영체제와 배포 방식
- 사용할 텍스트 모델의 최종 이름
- 이미지 생성 비용 한도
- 기존 자산을 실제로 가져올 수 있는지
- 자동 비전 검수를 기본 활성화할지
- WebP만 보관할지, PNG 원본도 장기 보관할지

이 항목은 구현 전에 `docs/08_REQUIREMENTS_INBOX.md`에서 결정한다.
